# Локальная HTTPS-проверка хранилища

Запуск:

```sh
STORAGE_TEST_TLS=1 bash dev/check_storage_local.sh /path/to/minio /tmp/anime-release-check.XXXXXXXX/package /path/to/nginx
```

TLS-режим требует ровно три аргумента, с IAM-режимом не совмещается. Новые
MinIO и nginx слушают только loopback 59438–59441. При занятых портах — отказ.
Стандартный deployment renderer даёт внутренний CORS listener 59440; дополнительный
тестовый TLS listener 59441 сохраняет Host с портом и исходный URI до него.
Ни production-конфигурация nginx, ни системные службы не изменяются.

`dev/storage_tls_fixture.sh` создаёт отдельный односуточный CA и сертификат с
SAN DNS:localhost внутри приватного каталога теста. Ключи создаются с umask 077.
CA не импортируется в ОС или браузер. Положительные запросы Req доверяют только
этому CA через cacertfile на конкретном соединении, без verify_none/insecure.
Отрицательный тест выполняется также через неизменённый Anime.Storage.HTTP.

## Результат 1 октября

`/tmp/anime-storage-check.LaUQfTqw`, exit 0, релиз qZTQ51we:

1. Доверенный тестовый CA и совпадающее имя сервера: подписанный GET успешен.
2. Без доверия CA: unknown_ca; production HTTP adapter тоже отклоняет соединение.
3. Доверенный CA, но адрес 127.0.0.1 вместо localhost: hostname_check_failed.
4. Подписанный HTTPS Range возвращает 206 и CORS; изменённая query получает 403.
5. Multipart: HTTPS OPTIONS, подписанный PUT, ETag, завершение через S3 и проверка байтов.

Базовый storage smoke также прошёл. Временные процессы остановлены. Формат Elixir,
синтаксис shell/JS проверены. Код приложения и production-шаблон не менялись;
полный набор 900 тестов здесь не повторялся.
Прежние пять IAM-сценариев повторены после изменения runner: CO3XruzA, exit 0.
Все четыре loopback-порта после проверок свободны.

Это не сертификат реального домена и не staging-приёмка: ACME/продление, публичный
DNS, внешний балансировщик, сетевой запрет обхода MinIO, браузер и плеер не проверены.
Положительный запрос с локальным CA использует тестовую конфигурацию Req, а не
новую поддержку пользовательских CA в runtime приложения. Системное доверие
production HTTP adapter не изменено. Тестовые root-ключи существуют только в fixture;
ограниченные IAM-профили проверяются отдельным режимом.
