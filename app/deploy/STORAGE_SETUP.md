# Начальная настройка MinIO

Команда: `bin/anime eval 'Anime.Release.storage_setup()'`.
Она явно меняет настройки хранилища и **не запускается автоматически** при boot,
migrate или seed. Перед настоящим запуском проверить endpoint, имена бакетов,
учётные данные и согласовать применение к конкретному окружению.
Рабочее хранилище при разработке этой команды не менялось.

Используются runtime MINIO_ENDPOINT, MINIO_REGION, MINIO_ACCESS_KEY_ID,
MINIO_SECRET_ACCESS_KEY и пять MINIO_BUCKET_* из .env.example. Сами файлы .env
не читаются. Настройки имён совпадают с генератором CORS: уникальные имена
3–63 символа, строчные латинские буквы, цифры, дефис. По умолчанию anime-originals,
anime-video, anime-previews, anime-posters, anime-avatars.
Список без обращения к API: `bin/anime eval 'IO.inspect(Anime.Storage.Setup.plan())'`.

## Порядок и ограничения

1. Проверить все имена, затем HEAD всех бакетов. Только 404 означает отсутствие;
   403, редирект и ошибка связи прекращают выполнение, не запускают создание.
2. У существующих бакетов прочитать versioning. При Enabled/Suspended, неизвестном
   ответе или ошибке — отказ до любых записей. Только исходное unversioned допустимо.
3. Создать отсутствующие бакеты и повторно проверить versioning.
4. Удалить bucket policy и проверить NoSuchBucketPolicy. Для обычного MinIO
   отсутствие публичной политики оставляет доступ подписанным запросам согласно IAM.
   BucketACL не вызывается.
5. Заменить lifecycle целиком: expiration префикса exports/ после 7 дней,
   как требует п.15. Прочитать правила
   обратно и проверить их ID, Enabled, prefix и интервалы.

Важно: lifecycle заменяет прежние правила. Команда сама не удаляет объекты,
но хранилище позднее удалит подходящие exports/ по этим
правилам, в том числе существующие. Это не режим «только посмотреть».
Старые версии объектов не удаляются; никаких DeleteObject/Version операций нет.
CORS API не вызывается: CORS настраивает nginx отдельно.

Обычный MinIO не поддерживает AbortIncompleteMultipartUpload в bucket lifecycle.
В окружении **самого сервера MinIO**, не Phoenix, оператор задаёт
MINIO_API_STALE_UPLOADS_EXPIRY=24h и MINIO_API_STALE_UPLOADS_CLEANUP_INTERVAL=6h.
Это серверная настройка всех бакетов: применять её к общему существующему серверу
можно только после согласования. storage_setup её не меняет и не проверяет.
Удаление выполняется очередным обходом, не ровно на границе 24 часов.
Источник: [конфигурация MinIO](https://github.com/minio/minio/blob/master/docs/config/README.md).
Проверка этих настроек и фактического истечения — отдельная часть приёмки.

Повторный запуск даёт те же настройки. Операции между бакетами не атомарны:
если поздний запрос упадёт, предыдущие изменения останутся; команда прерывается
с именем бакета и операции, после устранения причины её можно повторить.
Она не пишет ответ API или секреты в сообщение ошибки, не продолжает остальные
бакеты после отказа. Требует отдельного release eval, не работающего приложения.

Уже включённое версионирование нельзя вернуть в исходное unversioned-состояние:
[правила S3 versioning](https://docs.aws.amazon.com/console/s3/enable-bucket-versioning).
Команда намеренно не заменяет его на Suspended и не удаляет версии. Для такого
хранилища нужно отдельное решение о переносе/совместимости; автоматическое
исправление всех вариантов drift этим срезом не заявляется.

## Проверки

`test/anime/storage_setup_test.exs` проверяет создание/повтор, отказы API,
недопустимые имена и коллизии, ошибки без секретов, XML с DTD/неверным форматом,
readback и отсутствие CORS/объектных операций. Дополнительный loopback HTTP-stub
пропускает запросы через настоящий ExAws + Anime.Storage.HTTP с синтетическими
AWS4 заголовками. Это не проверка криптографической верификации подписи MinIO.

Release-проверка подтверждает наличие команды и расчёт пяти имён без API.
Реальный отдельный MinIO проверяется командой
`bash dev/check_storage_local.sh /absolute/path/to/minio /tmp/anime-release-check.XXXXXXXX/package`.
Runner создаёт собственный каталог и синтетические root-ключи, занимает только
свободные loopback-порты 59438/59439, останавливает собственный процесс при выходе.
Существующий endpoint и данные передать нельзя. Root-ключи теста не являются
примером прав рабочей provisioning-учётной записи.
