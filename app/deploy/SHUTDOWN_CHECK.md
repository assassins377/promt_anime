# Начальная фаза остановки веб-ноды

## Актуальное локальное состояние — 2 октября

Ниже сохранена история прежних проверок; её утверждения о недостающем коде
не являются описанием текущей реализации.

- После паузы10с listener закрывается, producer очередей приостанавливаются.
- Oban вынесен в Anime.Background; его завершение запускается параллельно
  ожиданию открытых веб-соединений, без автоматического рестарта Oban.
- Shutdown.drain_web ждёт30с, закрывает незавершённые HTTP и посылает
  отслеживаемым WebSocket :socket_drain. Общий дополнительный предел закрытия
  WebSocket —1с, не по секунде на каждое соединение.
- Потеря LiveTransports перезапускает Endpoint до начала rejection. После
  rejection guards WebSupervisor/DrainingAdapter запрещают запуск Endpoint
  и его Bandit child, чтобы не открывать порт заново.
- Реальный сетевой тест подтвердил ответ200 внутри окна, сохранение другого
  HTTP до границы, обработку события WebSocket на25с и закрытие1012 после30с.
- Дополнительные тесты проверили исчезновение сервера и внутренний restart
  Bandit после suspend. Это отдельные компонентные проверки, не полная приёмка.

Общий прогон тестов с этими изменениями начат, результат см. keep/HANDOFF.md
в корне проекта. Изменения пока локальные. Ещё не подтверждены настоящий
LiveView при SIGTERM полного релиза, совместный бюджет90с с Oban, HTTP2
и сценарий потери БД в новой реализации. Старые успешные проверки релиза
ниже не доказывают эти свойства нового кода.

Новый срез: после10с prepare вызывается Shutdown.stop_accepting(endpoint).
Он получает HTTP/HTTPS server через публичный Bandit.PhoenixAdapter.bandit_pid
и закрывает listener через ThousandIsland.suspend, не завершая активные соединения.
shutdown_listener_test.exs проверяет отказ нового TCP и ответ200 начатого запроса;
Полный CI36873575446 для0fd6d2b прошёл: tests-coverage, миграции/сиды,
JS/runtime/журналы/пороги/security и release/preflight success, exit0.
Это НЕ общий90с drain и НЕ запуск этой версии на стенде.
Phoenix.Socket.PoolDrainer в установленной версии начинает phx_drain при terminate
без30с ожидания; его стандартное поведение не заменяет требование grace period.

Реализовано в Anime.Application.prep_stop/1 и Anime.Shutdown:

1. Для запущенного endpoint устанавливается локальный признак shutdown.
2. `/readyz` отвечает 503 с `failed: ["shutdown"]`, не обращаясь к БД/MinIO.
   Уже начатая проверка повторно смотрит признак перед формированием результата.
3. До остановки дерева процессов выдерживаются 10 секунд. `/healthz` продолжает
   отвечать; новая готовность не объявляется. При старте приложения признак сбрасывается.
4. Для Bandit/ThousandIsland явно задан shutdown_timeout 30000 мс.
5. Реальный release runner проверяет SIGTERM, 503/no-store, health=200 и завершение
   не раньше 10 секунд и не позже 90. В тестовом режиме endpoint server=false
   callback не задерживает остановку тестового приложения.

Признак хранится в persistent_term, не требует БД, не пропадает при перезапуске
отдельного ребёнка супервизора и не добавляет таблицу к закрытому перечню ETS.

## Что не закрыто

Обновление 1 октября: зависший worker проверен реальным ожиданием 60002мс,
после остановки его процесс мёртв, Job остаётся executing/attempt1, не completed.
В config.exs явно задан Lifeline rescue_after=28800000мс и interval=60000мс
(раньше применялся стандартный час библиотеки). В отдельном Oban без dispatch
проверено: свежий executing не спасается; после искусственного старения только
fixture attempted_at на 28801с настоящий Lifeline возвращает available/attempt1.
Интервал опроса в этом тесте сокращён до100мс; восемь часов физически не ожидались.
Это проверка возврата в очередь, не доказательство ровно одного внешнего эффекта
или завершения повторной попытки. Удаляются только fixture Job.
Релиз Ko41gCMD, интеграция VXm38SZi exit0; потеря БД при SIGTERM снова16с.
Временные PostgreSQL/MinIO/релиз остановлены. Совместный бюджет HTTP/LiveView/Oban
и запрет новых монтирований всё ещё не приняты; старые checkpoint ниже — история.

Следующий срез Oban: shutdown_grace_period задан явно60000мс в config.exs.
dev/oban_drain_smoke.exs запускается offline eval в release database runner:
отдельный Oban, изолированные peer/notifier, очередь mailers с limit1,
реальная запись Job в новой тестовой БД. При остановке producer становится
paused, выполняемая задача завершается completed, следующая остаётся available
с attempt0. Только после проверки два собственных fixture Job удаляются,
поскольку модуль тестового worker не входит в production-релиз.
Проверка НЕ доказывает прерывание зависшей задачи через60с или её восстановление.
Результаты: релиз XWxow5PJ, 2xbyZ5TQ exit0, smoke PASS; SIGTERM при потерянной
БД —16с. Общий YyBr1rT9 exit0:910/0 за113.4с,93.61%(3444/3679), все стадии
и пороги прошли. Формат нового smoke проверен отдельно, временные процессы остановлены.

Следующая проверка 1 октября: расширенный dev/http_drain_smoke.exs прошёл оба
сценария. Зависший handler принудительно завершён через 30005мс; клиент получил
Req.TransportError с reason :closed, а не свой таймаут (у клиента 40с).
Проверяется диапазон 29–35с с учётом планировщика. Обычный активный запрос
по-прежнему завершается200 после закрытия listener. Серверы остановлены.
Это standalone HTTP/1 loopback, не общий бюджет endpoint с LiveView/Oban.
В этом срезе production-код не менялся; полный набор910 тестов не повторялся.

Это не полная реализация п.21. Не проверены WebSocket 1012, запрет новых LiveView-монтирований
после паузы и дренаж активных Oban-задач за 60с. Стандартный Phoenix socket drainer
не заменяется этим срезом. Последовательная остановка дочерних процессов ещё
не даёт доказательства общего бюджета 90с при максимальной нагрузке.
Медиа-нода, кластерный балансировщик и публичный staging также не приняты.

Сверка локальных библиотек: Oban.Config по умолчанию даёт shutdown_grace_period
15000мс; приложение теперь переопределяет его на60с. Phoenix.Socket.PoolDrainer
оповещает сокеты пакетами, а Phoenix.Socket преобразует socket_drain в restart
для закрытия1012. Это свидетельство кода библиотеки, не end-to-end проверка
LiveView. Простая установка всех независимых таймаутов не доказывает общий
90-секундный бюджет: требуется согласовать очередность/параллельность остановки.
Пауза producer доказана при остановке самого Oban, не немедленно по SIGTERM:
его очередь остановки в дереве приложения пока не изменена. До завершения
координации HTTP/LiveView/Oban публичное развёртывание не считается принятым.
